# PokéRem 1.2.0 polish QA

The existing 1.2.0 implementation was backed up locally before editing. The backup is temporary; the source changes are saved in this repository.

## Visual and usage evidence

Inspected the installed 1.1.4 sidebar read-only in RemNote. All interactive gameplay checks used `npm run preview:qa` at http://127.0.0.1:8081 with demo data and actual production UI components/reducers, without the RemNote SDK connection. No real flashcards were answered or edited.

Verified narrow 280px and 400px sidebar views, labeled navigation, compact arena toggle, XP doubler activation, rare doubler queue, review countdown, trainer team selection, locked combat inputs during staged motion, trainer victory/rewards, failed trainer catch preserving retry, successful retry, automatic party advancement on faint, trainer defeat with no catch offer, and reduced-motion combat. Controlled win/loss fixtures deliberately adjust enemy HP or levels to test outcome paths; these are not evidence of real-world battle balance.

A runtime rendering failure in the new trainer identity summary was caught in the preview and fixed; a rendering regression test was added. A separate save test verifies v3 progression/inventory/nicknames/collection/preferences survive upgrade and repeated serialization.

## Boundaries

Not yet verified inside RemNote: the updated sidebar's SDK load, fresh/upgrade installation, cross-widget sync, palette/queue actions, and installed-zip rendering. The QA preview cannot prove host integration. No live save has been migrated by this session.

## Local test and release

1. Export the existing save from PokéRem Settings.
2. Close all review queues and reload all RemNote windows before switching builds. The installed 1.1.4 reader accepts schema v3; 1.2.0 migrates to v4. Do not leave old widgets active while testing the new save format, and do not downgrade after migration without a backup.
3. Run `npm run dev` in the project. RemNote > Settings > Plugins and Themes > Build > Develop from Localhost, http://localhost:8080.
4. Confirm 1.2.0 in About and verify party, inventory, coins and progression match the export. Use an old deck for review tests.
5. Run `npm run release` to build the checked `PluginZip.zip`.
6. Update the existing PokéRem marketplace listing with that zip; keep plugin id `pokerem` unchanged. A local dev server or file save does not publish an update to other users. Confirm the marketplace accepts the version and complete any submission/review step it requires.

Official workflow: https://plugins.remnote.com/custom-css (local development and zip submission); https://help.remnote.com/en/articles/6030810-developing-front-end-plugins.
